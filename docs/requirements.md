# 安卓静默语音助手 Demo：需求文档

版本：2.0 · 2026-09-24。交付给开发 AI 使用；技术实现见 [技术设计](technical-design.md)。

## 1. 核心产品

一台闲置安卓手机固定放置并插电运行，持续录音，在手机本地完成 VAD、ASR 和控制调度。识别出完整话语后，**App 直接通过 HTTPS 调用 Jev**：第一次判断是否需处理及业务类别，家居控制等场景再判断目标、动作和参数。

没有唤醒词。助手不主动接话，不播报判断。页面用灰色小字显示识别、分类和忽略日志；执行时显示目标、参数、步骤和真实结果。日常闲聊默默忽略。

**本 Demo 不开发也不部署云端业务服务。** 原定甲骨文云和 `bitcoin001.cn` 暂不使用，未来需要远程访问或多设备协同时再评估。不要为了调用 Jev 引入 FastAPI、数据库、Caddy、WebSocket 或手机到云端的转发服务。

## 3. 首版范围

一个家庭、一台安卓语音端、一个可选电脑控制端，普通话，默认 `Asia/Shanghai`，可设置手机所在房间。闹钟在手机本地存储、调度、响铃；闹钟响铃不属于助手接话。

默认 observe 模式：可以判断和展示计划，但不产生实际设备副作用。能力被实际验证后再由用户设置 live；页面始终醒目显示模式。

首版不做开放式聊天/TTS、声纹识别、任意电脑命令、复杂多业务复合句、远程门锁开锁、云端同步或跨手机协调。设备出现在目录中不代表全部能力可控制。

## 4. 功能

### F01 监听与识别

用户在 App 中授予麦克风权限、点击开始。前台服务保持监听，页面关闭与熄屏时以继续运行作为目标，系统中断则准确显示。点击暂停必须释放麦克风。手机本地 VAD 检测语音、流式 ASR 显示字幕；final 才提交 Jev。原始音频默认不上传、不落盘。

### F02 静默判断

第一阶段判断 `actionable/ignore/uncertain` 与业务 `home_control/alarm/computer_control/daily_chat/other`。闲聊、复述、引用、否定、假设、目标不清时不执行，不语音追问；App 写出简短原因。只有明确请求才进入对应第二阶段。

### F03 家居

识别房间、设备别名、单设备或完整设备组，确定动作和参数。显式房间优先于默认房间。先校验完整计划，再通过已验证的米家控制接入执行，回读状态后展示结果。未接入、部分可用、不可用或参数越界明确拒绝；不自动找相似设备代替。设备组逐设备报告成功、失败或未确认。

目录使用用户米家极客版截图的真实名称、房间和可用性分组；ID 及参数由开发者按 [设备协议](device-control-contract.md) 自行生成。截图中的“完全可用”不等于每个动作都已通过真实执行验证。

### F04 闹钟

支持新增一次性/每日闹钟，明确目标的修改与取消。显示日期、时间、重复规则。手机成功持久化并调度后才显示成功。时间或目标有歧义时不猜。已成功设置的闹钟在断网后仍可响铃，提供停止和稍后提醒。

### F05 电脑

首版只支持绑定电脑的设置音量、暂停媒体、打开白名单应用。手机与电脑在同一局域网时可直接连接受鉴权的电脑代理。若不在同一网络，首版显示电脑不可达；不为此额外引入云服务器。代理失败或目标机器离线时显示未执行。

### F06 页面与日志

顶部显示监听、网络、Jev 连通性、observe/live 和默认房间；中部显示实时字幕与当前执行卡片；底部灰色小字显示最近判断与忽略原因。普通聊天只进入灰色日志。执行卡片显示原话、业务、目标、参数、下发、确认，不制作虚假百分比进度。后台不自动弹页、不抢焦点、不播报。

### F07 设置与历史

设置 Jev API Key、默认房间、模式、日志保留和必要置信度阈值；Key 不在页面明文回显，支持清除和更换。查看历史任务、闹钟、设备接入状态。真实设备映射和允许动作可以在 App 内维护或导入结构化配置。

## 5. 安全和数据

Jev Key 由用户在 App 内输入，用 Android Keystore 支持的加密存储；不得写入 APK、仓库或日志。直接调用意味着持有该手机及能访问其进程/设备的人可能窃取或滥用 Key，不能承诺客户端密钥绝对安全。服务端密钥隔离只有将来采用服务端代理才有。

Jev 会收到 final 文本，本地 ASR 并不意味着文字始终留在手机。partial、原始录音默认不发给 Jev。忽略类文字只短时显示并删除；控制历史默认保留 7 天，用户可清除。电脑代理须鉴权和动作白名单。

## 6. 非功能目标

- partial 在手机本地更新，可不上传；每段 final 对 Jev 第一阶段最多调用一次，明确家居控制才进入第二阶段。静音期间不产生网络请求。
- Jev 失败、超时或离线时 fail closed：不执行新控制，显示原因；已落地闹钟不依赖网络。
- 真实副作用按目标设备串行，重复 final、进程恢复、网络重试不能重复执行已确认操作；不明结果显示 unknown。
- 从说完到下发初始目标 P50 ≤2 秒、P95 ≤4 秒，网络和 Jev 实测后再判断是否可达。
- 目标手机完成 24 小时熄屏为主试运行，报告电量/温升/内存/系统中断；不承诺所有安卓机型永不被系统杀死。

## 7. 验收

| 编号 | 用例 | 通过条件 |
| --- | --- | --- |
| A01 | 开始、暂停、熄屏 | 状态准确，暂停释放麦克风，熄屏实测记录 |
| A02 | 日常聊天 | 不回复、不执行、不显示执行卡片 |
| A03 | 客厅灯控制 | 目标和参数正确；live 有真实状态反馈 |
| A04 | “打开灯，不，还是关掉” | 不执行中间字幕，以 final 判断 |
| A05 | 引用、否定、假设、电视声 | 不执行相关动作，保留失败样本 |
| A06 | 歧义或越界参数 | 明确未执行，无替代猜测 |
| A07 | 组控制部分失败 | 逐设备结果，整体 partial |
| A08 | 闹钟增改删 | 本地调度与显示一致；断网仍响已设闹钟 |
| A09 | 电脑动作 | 绑定电脑实际生效，离线明确失败 |
| A10 | Jev 网络失败/429 | 不执行，显示可恢复错误，不自动重复副作用 |
| A11 | 重复 final/进程重启 | 不重复执行已确认命令 |
| A12 | ≥100 条明确指令 | 约定环境端到端正确率目标 ≥95%，保留错例 |
| A13 | ≥8 小时背景环境 | observe 模式错误执行计划为 0 后才考虑低风险 live；不能据此声称永不误触发 |
| A14 | 24 小时真机 | 无未报告中断、持续内存增长或热保护停机，有日志证据 |

模拟计划、米家接口受理和真实设备状态改变分别报告，不混为一谈。上述均是待验收目标，不是现有成绩。

## 8. 交付与待补

交付源码、可安装 APK、模型文件/来源/许可证、设备目录与映射配置、电脑代理、构建说明、测试与真机记录。旧 Jev 项目仅供参考，新 App 独立运行。

开发 AI 先完成本地音频、Jev 直接调用、观察模式、闹钟和适配器接口。真实设备控制阶段需要取得物理设备 ID、实际可调用接口与授权方式；不能用自行定义的逻辑 ID 冒充真实米家 ID。目标手机型号与电脑系统待确认，但不妨碍先完成通用代码。

优先级：用户最新明确要求 → 本需求文档 → 技术设计 → 设备协议。此前 OCI/Sites 交接材料失效。
