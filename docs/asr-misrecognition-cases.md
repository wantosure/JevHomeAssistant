# ASR 误识别测试集

版本：1.0 · 2026-09-27。用于测试本地 ASR 输出常见同音/近音错误后，Jev 是否仍能恢复用户原本的设备意图。

## 数据文件

- [CSV 双语音频/回归索引](../testdata/asr-misrecognition-v1.csv)：可用表格工具检查或导入。
- [JSONL 结构化标准答案](../testdata/asr-misrecognition-v1.jsonl)：每行含原始用例、扰动文本和预期控制计划。
- [生成脚本](../scripts/build_asr_misrecognition_corpus.py)：从设备命令标准集确定性生成。
- 原始标准答案：[智能家居命令集](../testdata/smart-home-command-cases-v1.jsonl)。

## 覆盖与 ID 关联

当前为 **1,837 条可执行中文设备/分组命令，各生成 1 条误识别变体**。范围包括 803 条设备动作句、610 条设备口语变体和 424 条分组指令。无响应、闲聊、歧义和不支持动作不混入这组“应当执行”的正例。

每条记录用 `source_id` 指回原始中文命令；`id` 固定为 `ASR-{source_id}-01`。例如：

| id | source_id | reference_text | asr_text | 预期 |
| --- | --- | --- | --- | --- |
| `ASR-CMD-sim87_living_ac_001-01-02-01` | `CMD-sim87_living_ac_001-01-02` | 关闭客厅空调 | 关闭客厅空条 | `sim87_living_ac_001 / set_power / {on:false}` |
| `ASR-CMD-sim87_living_remote_001-01-01-01` | `CMD-sim87_living_remote_001-01-01` | 查询客厅电视遥控开关的状态 | 查询客厅点事遥控开关的状态 | 原查询动作与目标不变 |

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `reference_text` | 设定的用户原话/合成音频文本 |
| `asr_text` | 注入到 Jev 的模拟 ASR 错误转写 |
| `tts_text` | 用于生成音频的原始说法；TTS 不会因此保证实际 ASR 输出等于 `asr_text` |
| `error` | 扰动类型和被替换的字词，如 `电视 → 点事` |
| `source_id` | 对应标准设备测试用例 ID |
| `expected_decision/target_id/action/parameters` | 完全复用原用例预期，不因错字改变 |
| `evaluation_stage` | 固定为 `injected_asr_transcript_to_jev`，表明这是 ASR 输出注入后的 Jev 文字回归 |

## 测试方法

1. **Jev 鲁棒性回归**：将 `asr_text` 当作 ASR 最终转写提交，要求执行判定、设备/组 ID、动作和参数与 `source_id` 标准答案完全一致。不能只看意图分类正确。
2. **音频端到端回归**：对 `tts_text` 合成或真人录音，走目标手机实际 VAD/ASR，再将真实 ASR 最终文本送给 Jev。把实际识别文本和 `asr_text` 都保存下来；未命中指定扰动不代表测试失败，因为 TTS 不能强制 ASR 产生指定错误。
3. **定位错误**：如果 `asr_text` 注入后计划错误，是 Jev/别名/校验鲁棒性问题；如果实际 ASR 没识别成预设文本，是音频/ASR 结果，不可据此宣称 Jev 通过或失败。
4. 按 `error.type`、目标设备类型、动作和参数统计整计划准确率、设备误选、开关反向和参数错误。合成音频按 `source_id` 做数据切分，避免同一句原文及其误识别版本同时进入调参集和封存测试集。

当前扰动词表由常见同音、近音和切词错误构成，例如“灯→等”“空调→空条”“电视→点事”“窗帘→窗连”“客厅→客停”。这是一组**人工构造的压力测试文本**，不是从某个 ASR 引擎实测采样出来的错误分布；上线评测应继续用真实设备、口音、距离和噪声采集到的错误补充。

这些预期动作仅用于模拟测试。尤其是门锁等高影响动作，真实执行仍须服从应用自己的确认和安全规则，不能因为测试样本标为 `execute` 就绕过保护。

## 目录覆盖边界

例句“关闭电视”→“关闭点事”很适合作为目标设备明确时的语义恢复测试。不过当前截图目录只有“客厅电视遥控开关”这一输入/遥控条目，目录明确没有定义可关闭的电视执行设备。因此本版没有把它伪装成一个已映射的可执行样本；现有电视相关正例只查询遥控开关状态。若要把“关闭电视”加入执行类测试，需要先在模拟设备目录中明确电视本身的逻辑 ID 与 `set_power` 能力，再为其建立源用例和误识别关联 ID。
